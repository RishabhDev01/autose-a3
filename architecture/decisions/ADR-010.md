# ADR-010: Triggers are a label or `/autose` from collaborators; one run per issue at a time

## Status
Accepted (2026-11-21)

## Context
The workflow spends API quota and writes branches. Comments can be posted by anyone. Two triggers on the same issue, for example a label plus a comment, would race on the same branch.

## Decision
- **Events:**
  - `issues: [labeled]` where the label is `autose`;
  - `issue_comment: [created]` where the body starts with `/autose`;
  - `workflow_dispatch`, used internally for review round 2.
- **Who can trigger:** the job-level `if:` requires `author_association` to be OWNER, MEMBER or COLLABORATOR. Otherwise the job is skipped. Bot comments are ignored, so the workflow cannot trigger itself.
- **Concurrency:** `group: autose-issue-${{ issue number }}` with `cancel-in-progress: false`. A second trigger waits in the queue. Combined with `state.json` (ADR-004), it then resumes instead of starting again.
- `/autose` on a PR maps back to the issue it links to.

## Options considered
- **Label only.** Rejected. There would be no way to re-run without removing and re-adding the label.
- **cancel-in-progress: true.** Rejected. It would waste a half-finished run's quota.

## Consequences
- Runs on different issues run in parallel and share the Groq rate limits. The 429 backoff handles this.
- Fork PRs get no secrets, so the workflow only works inside our own fork. That is intended.
