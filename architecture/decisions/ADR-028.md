# ADR-028: Experiment E2 (full vs summary hand-off): keep full artifacts

## Status
Accepted (2026-11-22). Confirms [ADR-003](ADR-003.md) (hand-offs are files). Harness: fork PR [#34](https://github.com/RishabhDev01/tinydb/pull/34).

## Context
ADR-003 chose to give the builder the full `spec.md` and `design.md`, and planned experiment E2 to test that choice against a 5-line summary, measuring hidden-test pass rate and tokens.

Comparing the existing runs would not be fair: they used different code versions and different designs.

## Decision
- **A controlled harness.**
  - `HANDOFF=full|summary` selects what the builder is told. The summary is generated by rules, not by an LLM, so it cannot add or invent anything. It keeps every AC id, because the stage-4 checker requires one test per AC.
  - `autose/experiment.py` runs only stages 3+4, with the spec and design frozen from `autose/issue-N` and redesign switched off.
  - Each result is pushed to `e2/<variant>/issue-N-rK`, so the approved branches and PRs are untouched.
  - `autose-e2.yml` runs the matrix (5 issues × 2 variants × 2 repetitions) from one manual dispatch.
- **The hidden tests are run outside the fork, on Python 3.12.**
- **Outcome: keep `full` as the default.**

  | | full | summary |
  |---|---|---|
  | Hidden tests passed | **92/96** | 83/96 |
  | Runs passing all hidden tests | 8/10 | 7/10 |
  | Cost | $0.18 | $0.17 |

  Details are in `experiment/variants.md`.

## Options considered
- **An LLM-written summary.** This is closer to what a real "summarising" hand-off would be, but it adds a second variable (the summariser's quality), so the rule-based summary isolates the information effect.
- **Re-using the original runs.** Rejected, because the code versions and designs differ between those runs.

## Consequences
- **The summary saves about 5% of tokens.** In patch mode (ADR-016) the code shown dominates the request, so trimming the hand-off is not where cost lies.
- **The evidence is weak (n = 2 per cell; one run apart).** The report presents it as a direction that agrees with ADR-003, not as proof.
- **A side finding from the same runs:** the patch builder cannot edit module imports. On issue #5 every run's first attempt used `list[Any]` without `Any` being imported, which breaks `import tinydb` on Python 3.12; one run never recovered. Possible follow-ups:
  - show the module's import lines in `localize`;
  - allow an `### IMPORTS` block;
  - tell the builder that it can use only names that are already imported.
- **Evaluation-environment lesson:** local checks must use the CI Python version. A first pass on Python 3.14, which evaluates annotations lazily, scored the broken branch 9/9. All hidden-test results were re-run on 3.12, and none of the earlier ones changed.
