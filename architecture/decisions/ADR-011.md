# ADR-011: Model assignment based on the models our Groq key can actually use

## Status
Accepted (2026-11-21). Supersedes [ADR-006](ADR-006.md). Amends [ADR-009](ADR-009.md) by adding an injection classifier.

## Context
ADR-006 chose `llama-3.3-70b-versatile` for the reviewer and `qwen/qwen3-32b` for the judge. Before the first run we called `GET https://api.groq.com/openai/v1/models` with our free key. It returned:

| Model | Usable for us? |
|---|---|
| `openai/gpt-oss-120b` | yes: strongest general and tool-calling model |
| `openai/gpt-oss-20b` | yes: same family, smaller and faster |
| `qwen/qwen3.8-27b` | yes: **the only other general-purpose family** |
| `openai/gpt-oss-safeguard-20b` | policy classifier, not a coder |
| `meta-llama/llama-prompt-guard-2-86m` / `-22m` | prompt-injection classifiers |
| `allam-2-7b` | Arabic-focused, too weak for code |
| `whisper-*`, `canopylabs/orpheus-*` | speech, not relevant |

**What we learned:** ADR-006 was written from memory of Groq's catalogue. Model availability on a free key is an external fact that has to be checked, not assumed. That check is now a step in the README.

## Decision
| Role | Variable | Model | Why |
|---|---|---|---|
| Planner (stages 1–2) | `PLANNER_MODEL` | `openai/gpt-oss-120b` | best reasoning available |
| Builder (stages 3–4) | `BUILDER_MODEL` | `openai/gpt-oss-120b` | best tool calling available |
| LLM judge (stage 1 check) | `JUDGE_MODEL` | `qwen/qwen3.8-27b` | a **different family** from the planner it grades |
| Reviewer (stage 6) | `REVIEWER_MODEL` | `qwen/qwen3.8-27b` | a **different family** from the builder it reviews |
| Injection screen (new) | `GUARD_MODEL` | `meta-llama/llama-prompt-guard-2-86m` | classifies issue and comment text before any agent sees it |

**Experiment E1 variant** (ADR-008): the reviewer is set to `openai/gpt-oss-120b`, the same model as the builder, and compared against `qwen/qwen3.8-27b`.

**Injection screen.** If the guard scores issue text above 0.5 as malicious, the orchestrator stops at stage 0, writes the reason to `state.json`, and comments on the issue. Agents never see that text. This adds to ADR-009's `<untrusted>` wrapping; it does not replace it.

## Options considered
- **`gpt-oss-20b` as judge or reviewer.** Rejected. It is a different model but the same family, so it likely shares blind spots with the 120b planner and builder. Kept as the fallback if Qwen hits its rate limit.
- **`gpt-oss-safeguard-20b` as reviewer.** Rejected. It is tuned to classify content against a policy, not to review code.

## Consequences
- The judge and the reviewer share Qwen's rate-limit bucket. They run at different stages, so they rarely overlap.
- With only two general-purpose model families, "independence through a different model" has exactly one possible configuration. We note this as a threat to validity.
- All IDs live in repository variables, so if Groq's catalogue changes, nothing in the code changes.
