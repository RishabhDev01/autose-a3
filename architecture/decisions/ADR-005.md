# ADR-005: A home-grown tool loop over Groq, with a per-agent tool allow-list

## Status
Accepted (2026-11-21)

## Context
We can only use the Groq free API. The Claude Agent SDK needs Anthropic models, so it cannot be used. mini-swe-agent gives the model a raw bash shell, so "read-only" cannot be enforced. Groq exposes an OpenAI-compatible `/chat/completions` endpoint with function calling.

## Decision
- `autose/agent.py`, about 150 lines, uses the `openai` Python client with `base_url=https://api.groq.com/openai/v1`.
- Each agent is created with a list of Python tool functions. Only those are sent as `tools`. A call to any other name is rejected.
- Tools validate their paths:
  - `write_file` refuses `.github/`, `autose/`, `.autose/` (except via `write_artifact`), and any path outside the repo.
  - `run_tests` runs one fixed command (`python -m pytest -q`) with a timeout. There is no general shell.
- GitHub operations (`git push`, `gh pr create`, `gh pr comment`) are done only by orchestrator code, never by an LLM tool.

## Options considered
- **Own loop plus allow-list (chosen).** Permissions are enforced in code.
- **mini-swe-agent with litellm/groq.** Rejected. Its bash-only tool cannot be restricted.
- **A GitHub MCP server.** Rejected. Agents don't need GitHub access, and it would add attack surface.

## Consequences
- More code to own, but we can show exactly what each agent could do.
- The job token's permissions (ADR-008) add a second layer of enforcement.
