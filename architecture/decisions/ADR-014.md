# ADR-014: Tools adapt to how the model calls them

## Status
Accepted (2026-11-22). Amends [ADR-005](ADR-005.md) (tools), based on run 10.

## Context: what run 10 showed
Run [44939124496](https://github.com/RishabhDev01/tinydb/actions/runs/44939124496) on issue #3 was the first to get past the planner:
- **Stage 1 passed** with 4 testable ACs, accepted by the Qwen judge on the first attempt.
- **Stage 2 passed**: the design named `tinydb/table.py → Table.update` and the test file.
- The **builder then used all 40 turns without committing a single edit**. From the step log:

| Turns | Builder call | Outcome |
|---|---|---|
| ~13 | `read_file(line_start=…, line_end=…)` | **"bad arguments"**: our schema only had `start_line`/`max_lines` |
| 9 | `edit_file(old_string=…)` on `Table.update` | **"old_string not found"**: indentation differed from the file (e.g. 17 vs 16 spaces) |
| rest | re-reading lines 400–560 of `table.py` | context compaction (ADR-013) removed earlier reads, so it looped |

The spec and design were good. The failure was in the **interface between the model and our tools**. ADR-005 designed the tools for safety (path allow-lists) but assumed the model would call them exactly as specified.

## Decision
- **Accept argument aliases** (`line_start`, `line_end`, `start`, `end`, `offset`, `limit`) and ignore unknown arguments instead of raising an error.
- **Add `replace_lines(path, start_line, end_line, new_text)`.** The model reads files with line numbers, so it edits by line numbers too. It also supports insert/append (`end_line = start_line - 1`). The result echoes the new numbered lines, so the model need not re-read.
- **Make `edit_file` forgiving**:
  - strip copied `"123| "` prefixes;
  - if the exact text is not found, match ignoring indentation and re-indent the new text by the same offset (tested: a block shifted by 1 space is matched, its nesting kept, and it compiles);
  - otherwise return the closest-matching file lines in the error.
- **Builder prompt**: read once and act; prefer `replace_lines`; append tests at the end of the file.
- **Unchanged**: every safety check from ADR-005/009. The write allow-list, the forbidden paths and the fixed pytest command apply to the new tool too (tested: `replace_lines` on `.github/` is refused).

## Options considered
- **Raise `max_turns` above 40.** Rejected: it treats the symptom. At 8k TPM each turn costs about 30 s, and the loops would just get longer.
- **Give the builder a shell (`sed`, `patch`).** Rejected: it breaks the per-agent permission model (ADR-005).
- **Whole-file `write_file` for edits.** Rejected: `table.py` has 854 lines, about 8k tokens, which is beyond the per-request limit (ADR-013).

## Consequences
- Fewer wasted turns per edit. Fuzzy matching can, in theory, edit the wrong place if the snippet is ambiguous. It requires a **unique** match, and the build and test checks (ADR-007) catch breakage.
- Lesson for the report: **an agent's tool interface needs testing against real model behaviour, not just a spec.** The first tests (ADR-005 smoke test) used a scripted model that called the tools "correctly".
