# ADR-020: Agents get a stated turn budget and a forced finish

## Status
Accepted (2026-11-22). Amends [ADR-005](ADR-005.md) (agent loop), based on run 16.

## Context
Run [44979706645](https://github.com/RishabhDev01/tinydb/actions/runs/44979706645) was the first with a working Gemini key (ADR-019). Gemini answered correctly with tool calls, but the **spec planner made 20 read/grep calls and never called `finish`**.

It was researching the *fix*: `copy`, `_read_table`, storage internals, `self._storage.write`. That is design work, not spec work. The run stopped with `AgentStopped: max_turns=20`.

On the same issue, gpt-oss had finished spec in 3–5 turns. The loop's only exit was the model choosing to call `finish`, and a more thorough model never chose to.

## Decision
- **State the budget.** The agent's system message gets "you have N turns … call `finish` well before the budget runs out".
- **Force the end.** For the last 3 turns, the loop offers **only the `finish` tool** and sends "Turn t of N: stop exploring, call `finish` now with your complete answer". The model cannot keep exploring, so the stage ends with an answer, and the existing checks (ADR-007) decide whether that answer is good enough.
- **Spec prompt:** the spec describes behaviour, not implementation. 3–6 reads to ground API names are enough; the fix belongs to the design stage.

## Options considered
- **Raise `max_turns`.** Rejected: it costs more tokens and time, and gives no guarantee of finishing.
- **Force `tool_choice` to `finish`.** Not used: support for forcing a specific function differs between Groq and Gemini's OpenAI-compatible layer. Offering only `finish` works on both.
- **Accept the stop.** Rejected: an answer that then fails a check is more useful than no answer, because the redo loop can fix it.

## Consequences
- Every agent (planner, reviewer, builder in agent mode) now ends with an answer within its budget, or stops cleanly if it never calls a tool at all.
- A forced answer may be weaker. That is acceptable, because the spec checks, the judge, and the design and build checks catch weak answers and trigger redos.
- **Tested** with a scripted model that never calls `finish`:
  - turns 1–17 offer all tools, and turn 18 of 20 offers only `finish`, together with the wrap-up message;
  - the model then answers, and the stage returns it;
  - the system message carries the budget;
  - a model that only writes text still stops after 3 nudges.
