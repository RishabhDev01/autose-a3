# ADR-017: Agent instructions come from master; issue branches follow master

## Status
Accepted (2026-11-22). Amends [ADR-004](ADR-004.md) (state on the issue branch), based on run 13.

## Context: what run 13 showed
Run [44972517581](https://github.com/RishabhDev01/tinydb/actions/runs/44972517581) passed guard, spec and design, then **crashed**:

```
FileNotFoundError: .../autose/prompts/builder_patch.md
```

The build job starts on master. `python -m autose.orchestrator` imports its code from there, and then `setup()` checks out `autose/issue-3` (ADR-004). That branch was cut at `585c29b` (PR #2) in run 2 and never updated. Every **file the orchestrator read after the checkout** therefore came from that old commit: the agent prompts, the spec-writer skill and ARCHITECTURE.md.

So runs 10–13 had **version skew**: new Python code with old prompts.
- Run 12's builder prompt never mentioned `replace_lines`. ADR-014's tool code was live, but its prompt change was not. This partly explains why run 12's builder never used that tool.
- Run 13 only made the skew visible, because its prompt file did not exist on the old branch.
- The review job (ADR-008) checks out the PR head and runs `python -m autose.review` from it, so it would also have run old reviewer code.

## Decision
1. **Snapshot the instructions at import.** The orchestrator reads `autose/prompts/*.md`, `skills/spec-writer/SKILL.md` and `ARCHITECTURE.md` once, at import, from the master checkout the job starts on. Code and prompts are then always the same version, and nothing on an issue branch can change what the agents are told.
2. **Merge master into an existing issue branch** at the start of every run (`AutoSE: sync … with master`):
   - On a **fresh start**, master wins any conflict (`-X theirs`), because the code is reset to master anyway.
   - On a **resume** (quota stop, or review round 2), a conflict **stops** the run with a clear reason instead of guessing.
   - The agents' working tree, the PR, and the review job's checkout of the PR head then all have the current `autose/`, `skills/`, `ARCHITECTURE.md` and tests.
3. **Make the fresh-start reset complete** with `git checkout --no-overlay origin/master -- <dir>`, then check that nothing differs from master. A plain checkout only overwrites files. It left run 12's committed `tests/test_atomic_update.py` in place, which the local reproduction of run 13 caught (the build failed on all 3 attempts).

## Options considered
- **Delete and recreate the issue branch on every fresh start.** Rejected: it needs a force-push and loses the branch history that `runs.md` links to.
- **Run the agents from a separate master worktree and only edit code on the issue branch.** Cleaner, but a bigger change to every tool path. Merging plus snapshots fixes the skew with a small change.
- **Rebase the issue branch on master.** Rejected: rewriting history needs a force-push, and the commits are evidence.

## Consequences
- Each run on an existing branch adds a merge commit. The PR diff stays clean, because the merge base becomes current master.
- The report must say that **runs 10–12 used the PR #2 prompts**. Their failures are still real, but ADR-014's prompt change was never tested in them.
- Lesson: when an agent system lives in the repository it works on, **the version of its own instructions is part of its state**. It must be pinned like code, not read from whatever branch is checked out.
- **Tested** on a fresh clone of the fork's real `autose/issue-3` branch, with pushes disabled and a scripted model:
  - `setup()` merges master (base becomes `428cabe`);
  - `builder_patch.md` is present;
  - the leftover test file is deleted, and nothing in `tinydb/` or `tests/` differs from master;
  - the patch stage passes on attempt 1 (231 passed = 227 + 4).
