# ADR-024: Failing tests named with their errors, helper code always shown, doc-ID key types documented

## Status
Accepted (2026-11-22). Amends [ADR-016](ADR-016.md) (patch-mode builder), [ADR-002](ADR-002.md) (back to design on repeated failure) and [ADR-012](ADR-012.md) (ARCHITECTURE.md).

## Context
Run [44991617605](https://github.com/RishabhDev01/tinydb/actions/runs/44991617605) (run 22, issue #4, string doc IDs) was the first failure that was **not** caused by a limit or by setup. ADR-023 worked: the builder's answers were complete, or were reported as cut off. But:

- **Both designs had the doc-ID key types wrong.** TinyDB uses two forms inside `Table`:
  - `_read_table()` returns the raw storage dict, whose keys are `str`, so `get` looks up `table.get(str(doc_id))`.
  - The `updater` passed to `_update_table` sees keys already converted to `int`.

  Run 21's redesign assumed `str` everywhere, which broke `update` and `remove`. Run 22's designs assumed `int` everywhere, so `get(doc_id=1)` returned `None`.
- **Re-running run 22's final branch locally: 19 failed, 214 passed.** The failures were `test_get_ids`, `test_get_multiple_ids`, `test_contains_ids`, `test_doc_ids_json`, `test_move_document_between_tables`, …, plus 2 of its own AC tests.

Three things kept the implement ↔ test loop and the redesign (ADR-002) from correcting this:
1. **Feedback without information.** The builder got the last 2,000 characters of pytest's output: one-line summaries cut at 80 columns, with no line numbers and no assertion details. The redesign got the first 1,500 characters of that tail. Each agent could see *that* `get` failed, but not that it returned `None` for documents that exist.
2. **Helper code was never shown.** `localize` (ADR-016) adds the helpers a definition calls only while the 9,000-character budget has room. `get`, `update` and `remove` (about 9.6k characters) used it all, so `_read_table`, whose docstring says doc IDs are "NOT yet transformed", and `_update_table` were never in the request.
3. **The architecture note was too brief.** Invariant 2 said "Doc IDs are `str` in storage and `int` in memory" but not which dict inside `Table` is which. The builder did not get `ARCHITECTURE.md` at all.

## Decision
1. **`checks.failure_digest`** turns pytest's `--tb=short` output into one entry per failing test. Each entry has:
   - the test's file and line, with its source line;
   - the deepest frame when the error is raised inside `tinydb/`;
   - the first two `E` lines.

   Parametrized cases with the same error are merged (`[memory, json]`), and the digest is capped at 8 tests and 3,500 characters. The failure message now starts with the counts and the digest; the raw tail is used only when there is no FAILURES section (e.g. a collection error). In the builder's feedback the instruction and the digest come **first**, and the head is kept rather than the tail. The redesign gets 3,500 characters instead of 1,500.
2. **Helpers get their own budget in `localize`:** a third of the code budget, at least 2,500 characters. Duplicate callees, which had filled the 6-item window, are removed. Request sizes go from 9k/4k/2k (code/tests/failure) to 20k/6k/5k for Gemini; 9k/3k/2.5k is kept as the fallback after a 413.
3. **`ARCHITECTURE.md` invariant 2 now states the two key forms.**
   - `_read_table()` → `str` keys: read paths look up `str(doc_id)`.
   - The `_update_table` updater → `int` keys: write paths compare `int` IDs.
   - A caller's ID is converted to the form of the dict it indexes, and values that cannot be converted (e.g. `float('nan')`) match nothing.

   The builder now also gets `ARCHITECTURE.md` §4 (invariants), not only the planner.

## Options considered
- **Give the builder the full pytest output.** Most of it is passing-test dots and repeated `[memory]`/`[json]` cases, and it would crowd out the code.
- **Let the builder run tests itself** (the agent mode, ADR-005/014). Runs 10 and 12 showed that the tool loop wanders.
- **Leave `ARCHITECTURE.md` as it was** and rely on fixes 1 and 2. That would be a cleaner experiment, but the fact is easy to state and is exactly what an architecture document is for.

## Consequences
- **Change 3 is a human edit made after seeing run 22.** For issue #4 (and the hidden test `test_issue_2_string_doc_ids.py`), the report must say that the result was obtained with this clarification, and that the agents alone produced two wrong designs. It is context engineering, not a code change: the note describes how `table.py` works today and gives no fix for the issue.
- **The test log is now readable:** the run summary shows which tests failed and why, instead of `[... 11346 chars truncated ...]`.
- **Requests are larger:** about 6.6k tokens for issue #4's builder, still a small fraction of Gemini's limits.
- **Checked locally:**
  - the digest on run 22's real pytest output (2.3k characters, 8 tests + "3 more");
  - the digest on an error raised inside `tinydb/table.py` (shows that frame);
  - `localize` before and after (it now includes `_read_table` and `_update_table` at both sizes);
  - the TinyDB suite (228 passed).
