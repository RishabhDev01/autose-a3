# ADR-019: Planner and builder move to Gemini 3.8 Flash (paid); judge and reviewer stay on Groq

## Status
Accepted (2026-11-22). Amends [ADR-011](ADR-011.md) (models) and [ADR-015](ADR-015.md) (fallback).

## Context
- Groq's free tier gives each model **8K tokens per minute and 200K per day** (Groq rate-limits page). Runs 10–12 used most of a day's quota for both gpt-oss models, and run 14 stopped at design with `Used 199449/200000` and `195763/200000`. At about 8K tokens per hour of refill, five issues plus two experiments would take days of waiting.
- **Groq's paid Developer tier** (250K tokens/min, no daily cap, $0.15/$0.60 per 1M tokens for gpt-oss-120b) was the simplest fix, but its Billing page said "Developer tier upgrades are temporarily unavailable due to high demand" (checked 2026-11-22).
- **Gemini's free tier** on this account allows Gemini 3.8 Flash only **20 requests per day** (AI Studio → Rate Limit). One issue needs about 15–30 calls.
- **Gemini paid Tier 1** starts once a billing account is linked. For Gemini 3.8 Flash it allows about **1,000 requests/min, 2M tokens/min and 10,000 requests/day**, at **$0.75 input / $3.75 output per 1M tokens**, thinking tokens included (prices from Google's pricing page, valid to 2026-12-31). Gemini exposes an **OpenAI-compatible endpoint** that supports function calling and `reasoning_effort`, so our `openai`-client code works with a different base URL and key.

## Decision
- **Planner and builder use `gemini-3.8-flash`.** `llm.py` routes by model name: `gemini-*` goes to `generativelanguage.googleapis.com/v1beta/openai/` with `GEMINI_API_KEY`, and everything else goes to Groq. `reasoning_effort` is `low`.
- **The judge and reviewer stay on Groq's `qwen/qwen3.8-27b`** (free). Each uses little quota, and the reviewer and judge are now on a **different vendor and model family** from the planner and builder, which strengthens ADR-008's independence.
- **Fallback chain (ADR-015):** `gemini-3.8-flash` → `openai/gpt-oss-120b` → `openai/gpt-oss-20b`. Every fallback call is recorded as `fallback_calls`.
- **Least privilege:** only the build job gets `GEMINI_API_KEY`. The review job never sees it.
- `agent.py` sends each tool call back with **every field** the provider returned, not only `id`/`name`/`arguments`. Gemini can attach reasoning state ("thought signatures") to tool calls, and dropping it can break multi-turn tool use.
- A **spend cap** is set in AI Studio by the maintainer.

## Options considered
- **Wait for Groq's free quota to refill.** It works, but it limits throughput to roughly one issue per 2–3 hours of refill.
- **Groq Developer tier.** Preferred (no code change), but not available when checked.
- **Gemini free tier.** Rejected: 20 requests/day for 3.8 Flash. Flash-Lite allows 500/day but is a weaker model.
- **Move the judge and reviewer to Gemini too.** Rejected: the reviewer would then be the same model as the builder (ADR-008).

## Consequences
- **Estimated cost:** about $0.10–0.15 per issue for planner and builder, so roughly $2–5 for the assignment including re-runs and experiments. The real spend is on AI Studio's Spend page.
- **Comparability:** runs before this ADR used gpt-oss on Groq. The report must say which model did which run (`state.json` → `models`, and `tokens` → `fallback_calls`).
- **New quirks:** Gemini's 429s and 400s look different from Groq's. Our retry code handles the generic cases, and run logs will show anything new.
- **Tested** with mocked HTTP transports:
  - routing (Gemini URL and key vs Groq URL and key);
  - a Gemini tool call carrying `extra_content.google.thought_signature` is sent back unchanged in the next request, and the agent finishes;
  - `reasoning_effort: low` is sent;
  - a Gemini 429 with a 3,600 s wait falls back to Groq `gpt-oss-120b`.

  The tinydb suite and the workflow YAML are unchanged.
