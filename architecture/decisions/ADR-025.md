# ADR-025: Localize shows the module for a new module-level function

## Status
Accepted (2026-11-22). Amends [ADR-016](ADR-016.md) (patch-mode builder).

## Context
Run [44993561408](https://github.com/RishabhDev01/tinydb/actions/runs/44993561408) (run 25, issue #6, the `append` operation) passed guard, spec (4 ACs, judge passed on the first attempt) and design on the first attempt, in 50 s. It then stopped at implement with `the design names no existing definition or class under tinydb/ to change`.

The design was correct: add `append (NEW)` to `tinydb/operations.py`, next to `add`, `set` and `increment`.

`localize` (ADR-016) handles three cases:
- an existing definition: show its source;
- a class: show its outline;
- a new **method**: show the outline of its class. This is how `Table.pluck` worked in run 24.

It had no case for a new **module-level function**, so it returned no blocks and the orchestrator stopped. The builder's answer format already supports such a function (`### ADD <path> MODULE`), and `apply_edit` already applies it; only `localize` was missing the case.

## Decision
For a design row that names a new module-level function, `localize` shows **the module it goes into**:
- **in full if the file is 6,000 characters or less** (`operations.py` is 1.7k), because its sibling functions are the best guide to style and signatures;
- **otherwise as an outline:** the imports plus one line per top-level definition.

The block is labelled `module it goes into; add with ### ADD <path> MODULE`. After the first attempt the function exists, so later attempts show it as a normal definition.

## Consequences
- **All design-row shapes are now covered:** existing definition, class, new method and new module-level function.
- **A cheap stop:** the run stopped in about 1 minute, before any builder tokens were spent, and the `state.json` stop reason pointed straight at the cause.
- **Checked locally:**
  - run 25's row gives the whole `operations.py`;
  - a new function in `queries.py` (17k) gives an outline;
  - new methods and existing definitions are unchanged;
  - an `ADD … MODULE` answer applies, and the new function works;
  - on a second attempt the function is shown as a definition.

  The TinyDB suite passes (228).
