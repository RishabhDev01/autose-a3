# ADR-007: Checks are deterministic first; an LLM judge is used only for testability

## Status
Accepted (2026-11-21)

## Context
If the agent that did the work also decides whether its check passed, it will usually say yes. Most checks in the stage table can be computed from facts. "Every acceptance criterion is testable" cannot be computed fully.

## Decision
| Stage | Check | Kind |
|---|---|---|
| 1 | each `AC-n` line has Given/When/Then and a concrete expected value; plus judge: "can this be checked by an automated test? yes/no + reason" | regex + LLM judge (different model) |
| 2 | every file in the "Files to change" table exists or is marked NEW; every function name is found by `grep` | script |
| 3 | `pip install -e .` and `python -m compileall` exit 0; diff non-empty; only allowed paths touched | script |
| 4 | `pytest` exit 0 on the full suite; every `AC-n` is referenced in a new test | script |
| 5 | `gh pr view` state OPEN; `gh pr checks --watch` green | script |
| 6 | `verdict.json` matches the schema | script |

The **orchestrator** makes the final pass/fail decision. Agents can only claim they are done. Their claim is then checked.

## Options considered
- **Agent self-report.** Rejected. It cannot be trusted.
- **LLM judge for everything.** Rejected. Code checks are cheaper and less noisy.
- **Mostly deterministic (chosen).**

## Consequences
- The AC-to-test mapping only checks that a test exists for each criterion, not that it is a good test. Hidden tests and the reviewer cover quality.
