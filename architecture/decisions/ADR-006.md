# ADR-006: Models are Groq-hosted, with a different family for the reviewer and the judge

## Status
Accepted (2026-11-21). Model IDs to be confirmed against `GET /openai/v1/models` before the first run.

## Context
The budget is the Groq free tier, so the money cost is zero, but there are rate limits per model: requests and tokens per minute and per day. Limits are counted per model, so using several models also spreads the load. A reviewer from the same model family as the implementer tends to share its blind spots.

## Decision
Every model is set by a repository variable, so it can be swapped without changing code.

| Role | Variable | Initial choice | Why |
|---|---|---|---|
| Planner | `PLANNER_MODEL` | `openai/gpt-oss-120b` | strongest reasoning on Groq; spec and design need it |
| Builder | `BUILDER_MODEL` | `openai/gpt-oss-120b` | reliable function calling for code edits |
| LLM judge | `JUDGE_MODEL` | `qwen/qwen3-32b` | different family from the planner, so it doesn't grade its own style; cheap |
| Reviewer | `REVIEWER_MODEL` | `llama-3.3-70b-versatile` | different family from the builder; separate rate-limit bucket |

## Options considered
- **The same model everywhere.** Rejected. This is what experiment E1 measures (ADR-008).
- **A small 8B model for the builder.** Rejected. Its tool calls are unreliable in multi-file edits.

## Consequences
- Rate limits (HTTP 429) are expected. `agent.py` retries with exponential backoff and honours `retry-after` (ADR-009).
- Token usage is read from `usage` in each response, summed per agent in `state.json`, and reported in results.
