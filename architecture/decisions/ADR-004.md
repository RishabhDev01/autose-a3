# ADR-004: State lives on the branch in `.autose/issue-N/`, mirrored to Actions artifacts

## Status
Accepted (2026-11-21)

## Context
State must survive the gap between the build job and the review job, a re-dispatch for a second review round, and a manual re-run. Actions artifacts expire, and they cannot be seen from the pull request. PR comments are easy to read, but hard to parse back into state.

## Decision
- Each stage writes its artifact to `.autose/issue-N/`. The orchestrator commits it to the branch `autose/issue-N`.
- Files: `spec.md`, `design.md`, `diff.patch`, `test_report.md`, `pr.md`, `review-r1.md`, `review-r2.md`, and `state.json`.
- `state.json` records the current stage, attempt counters, review round, token usage per agent, and timestamps.
- The same folder is uploaded as an Actions artifact on every run.
- The review is also posted as a PR comment, so people can read it.

**Restarts.** The orchestrator reads `state.json` from the branch, if it exists, and resumes at the first stage that has not passed. A stage that passed is not redone, unless the review routed back to it.

## Options considered
- **Branch files plus Actions artifacts (chosen).** Durable, versioned, and visible in the PR.
- **Actions cache.** Rejected. It can be evicted, and it is not meant for state.
- **PR comments only.** Rejected. There is no PR before stage 5.

## Consequences
- The PR diff contains the `.autose/` files. They are excluded from the reviewer's diff with a pathspec, so the reviewer does not see spec or design (ADR-008). The human can delete the folder before merging.
