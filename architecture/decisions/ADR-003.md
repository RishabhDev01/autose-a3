# ADR-003: Hand-offs are files, not conversations

## Status
Accepted (2026-11-21). Tested in experiment E2.

## Context
Agents need enough information to do their job. Passing full transcripts to the next agent would leak reasoning into it, exceed Groq's token-per-minute limit, and anchor the next agent on earlier mistakes.

## Decision
| Receiver | Gets | Deliberately left out |
|---|---|---|
| Planner | issue title and body (wrapped in `<untrusted>`), `ARCHITECTURE.md`, A1 skill, repo read tools | — |
| Builder | `spec.md`, `design.md`, contents of the files named in `design.md`, repo tools | the planner's conversation, issue comments |
| Builder (retry) | the above plus the last test output, truncated to 3,000 characters | earlier full test logs |
| Reviewer | issue text, `git diff main...PR-head`, repo at PR head, `run_tests` | spec.md, design.md, test_report.md, and every agent transcript (see ADR-008) |

## Options considered
- **Full artifacts plus repo access (chosen).**
- **Summaries only.** Rejected for now. A summary loses the exact AC wording that the tests must match.
- **Full transcripts.** Rejected. Too many tokens, and they break reviewer independence.

## Experiment E2
The builder is given either the full `spec.md` and `design.md`, or a 5-line summary of them. We compare hidden-test pass rate and tokens used across the 5 issues.

## Consequences
- Each artifact must stand on its own. The templates force sections such as "Files to change" and "Acceptance criteria".
