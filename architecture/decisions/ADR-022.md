# ADR-022: Planner token budget sized for Gemini, and budgets set by repo variables

## Status
Accepted (2026-11-22). Amends [ADR-009](ADR-009.md) (token budgets).

## Context
Run [44990628889](https://github.com/RishabhDev01/tinydb/actions/runs/44990628889) (run 20, issue #4) passed guard and spec (5 ACs, judge passed on the first attempt). It then stopped in design with `BudgetExceeded: planner used 153744 tokens, budget 150000` after 34 planner calls.

The planner budget is **per run** and shared by spec and design. It was set to 150k when the planner ran on Groq's free tier, where the 8K-TPM limit already kept each request small (ADR-013).

On Gemini (ADR-019) the planner keeps up to 15,000 characters of context, about 4k tokens, on every turn. Spec and design can each take up to 20 turns. Run 17 (issue #3) already used 126k, so the budget had almost no margin. Issue #4 is a feature, and its design needed more reading than a one-line bug fix.

The budget is a cost guard, not a rate limit. At Gemini 3.8 Flash Tier 1 prices ($0.75 per 1M input tokens), 153k tokens cost about $0.12.

## Decision
- **The planner budget is 400k tokens per run,** about $0.30 at most. This covers two full 20-turn stages plus one redo.
- **The budgets come from repository variables** `PLANNER_BUDGET`, `BUILDER_BUDGET` and `REVIEWER_BUDGET`, with defaults 400k / 120k / 250k. The maintainer can change them without a code change, the same way as the `*_MODEL` variables.
- The builder budget is unchanged. Patch mode (ADR-016) uses about 3k tokens per attempt.

## Options considered
- **A separate budget per stage.** This is cleaner accounting, but a bigger change. Spec already ends in a few calls (ADR-020), so one shared budget is enough.
- **Cut the planner's context.** This would make design less grounded, and design quality decides whether the patch builder succeeds.

## Consequences
- The cost ceiling per run rises by about $0.19. This is well inside the ₹1,000/month cap.
- A run that still hits the budget stops at the same stage with the same message. The maintainer can resume it with `workflow_dispatch` (`start=design`).
