# ADR-029: A label or comment trigger after a released run starts fresh

## Status
Accepted (2026-11-22). Amends [ADR-016](ADR-016.md) (resume on restart) and [ADR-010](ADR-010.md) (triggers). Fork PR [#35](https://github.com/RishabhDev01/tinydb/pull/35).

## Context
While recording the demo, we added the `autose` label to issue #5. Run [45004971036](https://github.com/RishabhDev01/tinydb/actions/runs/45004971036) (run 29) started correctly, but it logged `setup: ok start=release`: it reused PR #23, re-checked CI and re-ran only the review.

The orchestrator commits `state.json` to the issue branch **before** the release stage. This is deliberate: nothing is committed after CI, so the PR head stays the commit that CI tested.

A finished run therefore leaves `status: running, next: release` on the branch. A later label or `/autose` comment uses `start=auto`, so it "resumed" at release instead of starting a new run. Runs 17 to 27 had used `workflow_dispatch` with an explicit stage, which is why we had not seen this.

## Decision
With `start=auto`, if the saved state says `next=release` and the status is still `running`, and an **open PR from the issue branch exists**, the previous run had released. The new run therefore starts fresh at `guard`, which also resets the code and counters (ADR-023).

Unchanged:
- quota pauses (`resume_at`) resume where they stopped;
- stopped runs restart fresh, as before;
- a release that never opened a PR is retried at release;
- an explicit dispatch stage is honoured.

## Options considered
- **Commit the final `released` status after CI.** Rejected: it adds a commit after CI, so the PR head would no longer be the tested commit (the reason for the current design).
- **Store run status outside the branch** (for example, in a PR label). This would be possible, but it is a second source of truth; the open PR is already that signal.

## Consequences
- **Label and comment triggers now give a complete run on an issue that already has a PR.** Run 30 (label on issue #5) and run 31 (`/autose` on issue #6) both logged `start=guard`, went through every stage and ended with an approving review.
- **Both rebuilt branches still pass all of their hidden tests** (9/9 each).
- This is another defect that appeared only when the system was used the way a maintainer would use it, not through the developer's own manual dispatch.
