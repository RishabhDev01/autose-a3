# ADR-027: A review-only workflow for seeded PRs and the reviewer-model experiment

## Status
Accepted (2026-11-22). Implements the calibration in [ADR-008](ADR-008.md) (independent reviewer) and serves experiment E1.

## Context
ADR-008 calls for calibrating the reviewer on 5 seeded PRs (4 with a known bug, 1 correct) and for comparing reviewer models on them (E1). But the reviewer only ran inside the main AutoSE workflow, after a build. A hand-written PR has no build, and the Gemini key exists only as a repository secret, so the reviewer cannot be run locally without exposing it.

## Decision
- **New workflow `.github/workflows/autose-review.yml`** (fork PR [#28](https://github.com/RishabhDev01/tinydb/pull/28)). It is started by hand with `pr`, `issue` and `reviewer_model`, and runs `autose.review` on that PR's head. There is no build and no post job, and it posts no comments. The verdict goes to the job summary and to a `verdict.json` artifact.
- **The reviewer's code always comes from master.** A sparse checkout puts it in `runner/`; the PR's own `autose/` folder is deleted before the run, and `PYTHONPATH` points at `runner/`. This was checked locally: a tampered `autose/review.py` in the PR copy is not the one loaded. A PR under review therefore cannot change its own reviewer.
- **Least privilege:** a read-only token (`contents`, `pull-requests`, `issues: read`); inputs reach the shell only through environment variables.
- **The seeded PRs are written like ordinary PRs**, each with a passing test file, so CI is green on all five. The answer key lives in the submission repo (`experiment/seeded_prs/README.md`). The reviewer sees only the issue and the diff, not the PR title or description.

- **4/4 bugs caught, 0 false alarms**, and each finding names the seeded defect and its line.
- Together with the AutoSE PRs, the reviewer agreed with the ground truth on **10/10** PRs: #17, #22, #23 and #25 were approved and pass all their hidden tests; #26 was rejected for test gaming and fails 2 hidden tests.

## Consequences
- **E1 can rerun the same five PRs** with `reviewer_model` set to the builder's model (`gemini-3.8-flash`) or to a Groq model, with no code change.
- **Five seeded PRs is a small sample,** and each bug is visible in the diff. The report must say that this measures the reviewer on diff-visible, single-defect PRs, not on subtle multi-file bugs.
- The review-only workflow is a second path to the reviewer, so it keeps the same independence rules as stage 6: no access to `.autose/`, `autose/` or `.github/`.
